Vedashri Travels

User manual, hosting guide, and how to publish this app on GitHub. India-only car travel: customer booking site and owner dashboard on one server.

1. The two website links

AudienceURL pathPurpose
Customer/Home, book, fleet, my trips, pay, AI assistant
Customer app/app.htmlMobile-sized entry; add to home screen
Owner/owner.htmlCompany, fleet, rates, drivers, staff, bookings, accounts, reports

Owner PIN (change after first login): 2145

2. Customer home (always the start)

Every load opens the home page. From here the customer picks Local, Airport or Outstation, or sends a query to the owner.

Figure 1. Customer home — trip types and booking entry.

3. Booking, map and fare

  1. Choose Local, Airport or Outstation.
  2. For airport, choose Pickup or Drop (different fixed rates per car).
  3. Choose Single or Return. Return bills both ways on distance slabs.
  4. Type From and To from the India place list. The map moves to that place. You never enter coordinates.
  5. Set start and end dates. Extra days between them are waiting days, charged per car per day.
  6. Pick a car. The estimate updates: slab fare + waiting.
  7. Pay with GPay, UPI, card or cash, then Confirm booking. A WhatsApp greeting link opens.

Figure 2. Place names drive the map. Fare uses distance slabs, return multiplier and waiting days.

4. How fares are calculated

Each car has its own rates, set by the owner.

PieceRule
Slab 1Fixed amount up to slab-1 km (example: first 80 km = Rs 2000)
Slab 2Fixed amount from after slab 1 up to slab-2 km (example: 81–300 km = Rs 3500)
Slab 3After slab 2: slab-2 rate + leftover km × per-km rate
ReturnDistance is doubled before slabs (local / outstation)
WaitingDays between start and end × waiting per day for that car
AirportFixed pickup or drop; return airport = pickup + drop. No slab.

5. Payment gateway

On confirm, the Pay page shows the company GPay UPI ID and QR. Cash stays pending until the owner marks the trip completed. GPay / UPI / card are marked paid at booking.

6. My trips

Enter the 10-digit mobile used at booking. Approve, cancel, or mark complete. Cancel and complete trigger WhatsApp greeting text.

7. AI assistant

The gold AI button answers fares, cars, waiting, payments and contact in English. It does not replace booking.

8. Owner dashboard

Figure 3. Owner dashboard with KPIs and charts.

  • Company — owner name, company, address, phones, WhatsApp, GPay ID, PIN, logo and QR upload.
  • Fleet — add / edit / delete cars, image upload, 3 slabs, waiting/day, airport pickup and drop.
  • Drivers / Staff — details, salary, trip charge; edit or delete.
  • Bookings — live customer bookings and queries; approve / complete / cancel.
  • Accounts — expenses; income from non-cancelled bookings.
  • Reports — daily, monthly, annual charts; CSV export for bookings, staff, drivers, expenses.

9. Run on your computer

git clone https://github.com/YOUR_USER/vedashri-travels.git
cd vedashri-travels
npm install
npm start

Then open http://localhost:3000 and http://localhost:3000/owner.html

10. Put the two links on the web

Need Node 18+ and a small always-on host (Railway, Render, a VPS, or any Linux box).

Option A — Render / Railway

  1. Push the repo to GitHub (section 11).
  2. Create a new Web Service from that repo.
  3. Build: npm install. Start: npm start.
  4. Set PORT if the host requires it (the app already reads process.env.PORT).
  5. After deploy:
    • Customer: https://YOUR-HOST/
    • Owner: https://YOUR-HOST/owner.html
    • App: https://YOUR-HOST/app.html

Option B — VPS (Ubuntu)

sudo apt update
sudo apt install -y nodejs npm nginx
git clone https://github.com/YOUR_USER/vedashri-travels.git /var/www/vedashri
cd /var/www/vedashri
npm install
# keep it running
npx --yes pm2 start server.js --name vedashri
npx --yes pm2 startup
npx --yes pm2 save

Nginx example (one public port, both links):

server {
  listen 80;
  server_name travels.example.in;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
  }
}
Add HTTPS with Let's Encrypt (certbot --nginx) before sharing GPay/QR links with customers. Keep data/store.json backed up; that file is the live database.

11. Publish the app to GitHub

  1. Create a free GitHub account at github.com if needed.
  2. New repository named vedashri-travels (Public or Private). Do not add a README on GitHub if this folder already has one.
  3. In the project folder:
git init
git add .
git commit -m "Vedashri Travels customer and owner sites"
git branch -M main
git remote add origin https://github.com/YOUR_USER/vedashri-travels.git
git push -u origin main

Replace YOUR_USER. GitHub will ask for a personal access token as the password.

Later updates:

git add .
git commit -m "Describe the change"
git push

Optional GitHub Pages only serves static files. This app needs Node, so use Render/Railway/VPS for the live customer and owner links. GitHub still holds the source and this PDF.

12. Customer mobile app link

Share /app.html. On Android Chrome: menu, Add to Home screen. On iPhone Safari: Share, Add to Home Screen. That icon opens the customer flow.

13. Data and limits

  • Places are India-only. Map geocoding is restricted to India.
  • Bookings, cars, staff live in data/store.json (no extra database).
  • WhatsApp greetings open wa.me with the owner number; they are not an official WhatsApp Business API.
  • GPay QR is the image the owner uploads. There is no live bank capture in this small build.
